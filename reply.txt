- Section 6: the authors might consider whether the remote peer is better described as a remote proxy than as an adapter.
REPLY
The distinction between different design patterns is sometimes vague. We looked at some discussion online:
https://stackoverflow.com/questions/37692814/what-is-the-exact-difference-between-adapter-and-proxy-patterns
https://stackoverflow.com/questions/350404/how-do-the-proxy-decorator-adapter-and-bridge-patterns-differ
https://en.wikipedia.org/wiki/Proxy_pattern
Our understanding is that the proxy pattern should keep the same interface, while the adapter pattern
does adapt an interface to another. See for instance in the Wikipedia citation:
"For the client, usage of a proxy object is similar to using the real object, because both implement the same interface".
In our case, we are adapting a web service to the ABI and their interfaces
are definitely different. So the service and the remote are adapters while service+remote is a proxy pattern.
We clarify this now as follows now in the paper:
"The compound use of a service and a remote adapter (Fig 6c) can also
be seen as an instance of the proxy design pattern."
