This article shows that the use of a single abstract interface to
interact with a blockchain allows one
to write testcases for smart contracts once,
and reuse them against different implementations of the blockchain
under testing. Therefore, tests become a useful non-regression check
for modifications to the blockchain peer itself, both small and radical,
such as the replacement of the consensus algorithm of the blockchain,
something that actually occurred
during the development of the Hotmoka blockchain.
In general, blockchains might consist of a varying number of peers
and might have different consensus algorithms. There might be
local peers (directly contacted
as an object in RAM) and remote peers (contacted through a network).
The use of a single abstract blockchain interface
respects the open-closed software engineering
principle. Moreover, by stubbing the abstract blockchain interface,
it becomes possible to execute the
testcases quickly enough to allow their use during continuous integration,
without any code modification, which further supports their use as a
non-regression check.
